# 明日回声：MVP 约定

## 核心体验

把预测、概率和到期时间一起封存，之后诚实地记录结果。它是私人预测日记，不是竞赛或可验证的第三方预言系统。到期之前可以阅读原预测，但不能改写或结算。用户对结果自行负责。

示例：预测「今天下班前把那封邮件发出去」，概率 80%，一小时后揭晓。发生时得分 96，没发生时得分 36。这样既奖励预测准确，也让过分自信的错误留下痕迹。

## 页面

| 路径 | 内容 |
| --- | --- |
| `/` | 简短产品介绍、静态示例、登录和开始按钮 |
| `/login`、`/signup` | 邮箱密码登录注册，明确错误提示；成功进入收件箱 |
| `/app` | 私人卡片列表，三状态筛选，新建表单、结算表单、统计摘要 |

布局：浅米白信纸背景、深墨色文字、青绿色强调色，日期邮戳和信封卡片。手机单列、桌面双列，不依赖外部图片。空状态解释如何创建第一条预测；加载、失败、提交成功均有反馈。卡片禁用结算按钮时给出原因，倒计时归零后重新向服务器取状态。

## 行为

1. 用户可以邮箱密码注册、登录、刷新后保持登录、退出。由 Better Auth 处理密码哈希、会话 cookie 和认证防护，不自行发明密码或 token 方案。首版不做邮箱验证、找回密码或邮件发送；界面不得声称邮箱已验证。
2. 创建时输入标题 1–120 字、可选说明最多 1000 字、整数概率 0–100、揭晓延时。固定延时选项为 1 分钟、1 小时、24 小时、7 天。服务器把延时换算为 `unlock_at`，不接收客户端指定的过去时间。
3. 提交即封存。无编辑、删除和草稿；用户可读自己的所有内容。
4. 到期可填写布尔结果和最多 500 字复盘。未到期、已结算均不可结算；并发双击只有一次成功。
5. 卡片显示标题、概率、状态、时间、结果和得分。只显示当前用户的数据，不提供公开分享。
6. 摘要显示总条数、待揭晓数、已结算数、平均得分；无已结算数据时为「暂无」，不能伪装为 0 分。不增加图表库。

## 数据和状态

认证表使用 Better Auth 与 Drizzle 官方生成的 schema。唯一业务表 `capsules`：

| 字段 | 约束 |
| --- | --- |
| `id` | UUID 主键 |
| `user_id` | 认证用户外键，非空；与创建时间组成索引 |
| `title`、`note` | 上述长度限制，title 非空 |
| `probability` | 整数 0–100 |
| `created_at`、`unlock_at` | `timestamptz`，由数据库时间计算 |
| `outcome` | 可空 boolean，false 是有效结果 |
| `reflection` | 可空文本，最多 500 字 |
| `resolved_at` | 可空 `timestamptz` |

状态不重复存储：`resolved_at != null` 为 resolved，否则数据库 `now() >= unlock_at` 为 ready，其余为 sealed。用约束确保 outcome 与 resolved_at 同时为空或同时有值。

一次性结算使用类似 `UPDATE ... WHERE id = ? AND user_id = ? AND resolved_at IS NULL AND unlock_at <= now() RETURNING ...` 的原子操作。数据库只允许服务端持有凭据。

得分为 `round(100 * (1 - (p - y)^2))`，p = probability / 100，发生 y=1，没发生 y=0。先以未舍入值计算所有已结算条目的平均分，再把平均值四舍五入为整数。此分数不等于「正确率」。不存冗余分数字段。

## 服务端接口

认证挂载 `/api/auth/*`。应用接口可使用 Route Handlers：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/capsules` | 当前用户全部卡片，服务端状态和 serverNow，最新在前 |
| POST | `/api/capsules` | 接收 title/note/probability/unlockDelaySeconds；延时只接受 60/3600/86400/604800 |
| POST | `/api/capsules/:id/resolve` | 接收 outcome（boolean）及 reflection |
| GET | `/api/stats` | 当前用户统计 |

未登录 401，非法参数 400，其他用户或不存在的 UUID 404，未到期或重复结算 409。所有写入均检查认证与同源请求，认证 cookie 保留库的安全设置。禁止信任 body/query 中的 user_id、score、resolved_at。私有响应使用 no-store，不得共享缓存。

JSON 字段、响应封装和认证集成以 [CONTRACT.md](CONTRACT.md) 为准，前后端不得独立改变契约。

## 实现范围

单 Next.js 项目；Neon Postgres 持久化；Drizzle 版本化迁移；Better Auth；Vercel。提供 `.env.example`（仅占位符）和 README 本地启动、迁移、测试说明。用数据库迁移命令独立部署表结构，不在每次请求中建表。

明确不做：社交、支付、邮件、AI 总结、文件上传、后台定时器、多租户组织、管理后台。到期状态按读取时计算，不需要 cron。
