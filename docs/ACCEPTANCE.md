# 交付验收

每项报告 PASS / FAIL / BLOCKED，附测试命令或公开安全的证据。不得用「代码看起来正确」代替真实执行。

| ID | 验收 |
| --- | --- |
| A1 | 新账号注册、退出、重新登录；刷新后会话仍有效，错误密码被拒绝 |
| A2 | 未登录直接读写业务 API 返回 401 |
| A3 | 用户 A 创建预测；用户 B 列表和统计均看不到它，对 A 的 UUID 结算返回 404 |
| A4 | 创建后刷新页面、重新登录仍可读取，证明是数据库持久化 |
| A5 | 1 分钟预测提前结算返回 409；实际等待 60 秒后能结算；更改浏览器时间不能提前揭晓 |
| A6 | 同时发两个结算请求，恰好一个成功、一个 409；结果只计入统计一次 |
| A7 | false 结果正确存储；80% 发生得 96 分，80% 未发生得 36 分；0%/100% 边界正确 |
| A8 | 概率 -1/101/小数、空标题、非法延时、非布尔 outcome 被拒绝；空统计为暂无 |
| A9 | 无认证/数据库密钥出现在 Git、公开页面或客户端包；无生产测试后门 |
| A10 | 390px 和 1440px 截图；新建、状态筛选、结算、退出可操作，无严重控制台错误 |
| A11 | 格式/静态检查、类型检查、单元和数据库集成测试、production build 均通过 |
| A12 | Vercel 部署可以完成 A1/A4/A5，给出 URL；独立项目/数据库，未碰已有项目 |

本地/CI 用 PostgreSQL 服务容器和真实 Better Auth 会话测 A2/A3/A6；测试可在独立测试数据库修改时间以加速，但线上不能提供时间或认证旁路。A5 在真实部署至少完整执行一次 1 分钟流程。

应用 PR 必須包含 `docs/DELIVERY.md`：部署 URL、PR URL、依赖版本、数据库提供商、环境变量名称（不含值）、迁移方式、上述验收表、测试结果、剩余问题。用户账号密码和原始日志不得公开。
